# 硬约束（Hard Constraints）

> **用途**：列出 Covenant 不可协商的不变量。任何设计、实现、AI 行为违反其中任何一条，即为缺陷，不因"方便"而豁免。
> **目标读者**：实现者、评审者、AI Agent（生成补丁前必须自检）。
> **状态**：v0，随格式冻结而冻结；修改需 ADR。
> **关联文档**：[format-spec-v0.md](../design/format-spec-v0.md)、[ai-trust-boundary.md](../design/ai-trust-boundary.md)、[profiles-catalog-v0.md](../design/profiles-catalog-v0.md)。

---

## H1 `.cvn` 是唯一权威，其余皆派生物

`arch/**.cvn` 与 `covenant.yaml` 是事实源；`dist/*.html`、`*.svg`、`*.png`、`.cvn-cache/` **全部可删除重建**。

- 违反：把用户在某次 HTML 会话里的修改当作已生效（未 apply 即未生效）。
- 校验点：`build` 必须是纯函数；删除 `dist/` 与缓存后重跑结果一致。

## H2 语义与画面分离

坐标、颜色、笔迹属于**视图**，不属于元素；坐标只能经 `view.layout.pins` / `view.canvas` 进入文档。

- 违反：把 `x/y` 写进 `element`。
- 校验点：L1 schema 不允许 element 出现位置字段。

## H3 ID 永不复用

元素/关系被删除后，其 `id` 不得再分配给新对象。

- 违反：合并两份文档时把同名 id 指向不同语义。
- 校验点：L2 检测"同 id 已出现在历史 rev 中但语义不同"→ error。

## H4 人工批注不可被 AI 修改或删除

`author: human:*` 的批注：AI 只能追加 `thread`，不能改 `status`、`body`、`resolution`，不能删除。

- 违反：AI"顺手"把人写的问题标成 resolved。
- 校验点：patch 白名单拒绝；L1 校验 `annotation/immutable`。

## H5 补丁必须带 `base_rev` 与 `intent`

无 `base_rev` 的写入请求一律拒绝（乐观锁）；无 `intent` 的补丁无法审计。

- 违反：基于过期版本的补丁静默覆盖新变更。
- 校验点：apply/patch 入口强制校验，缺失即 exit 3。

## H6 `breaking` 变更必须人工批准

删除仍有入边引用的元素、改变关系主语义、删除视图，均属 `breaking`；未获 `approved_by` 不得落盘。

- 违反：AI 悄悄删掉"看起来没用"的元素，破坏下游任务。
- 校验点：语义 diff 分类器 + 门禁。

## H7 未知即错误，不得静默忽略

非 `x-` 前缀的未知字段、剖面词表外的 `kind`、未注册的规则 `type`，全部报错。

- 违反：拼写错误（`summry`）被丢弃，图悄悄缺语义。
- 校验点：L1/L3 严格模式；`--allow-unknown` 仅用于迁移期且必须显式。

## H8 渲染确定性

渲染期间禁止 `Math.random`、`Date.now`、网络、环境变量；遍历顺序必须按显式排序键。

- 违反：同样输入两次输出不同，黄金测试与 AI 预判失效。
- 校验点：CI 连渲 3 次哈希一致。

## H9 默认不联网

渲染、校验、digest、构建默认零网络请求（含字体、图标、遥测、CDN）。

- 违反：内网环境打不开，且数据外泄。
- 校验点：CSP `default-src 'none'`；构建产物扫描外链；`--ai` 才开外发。

## H10 单一事实源

同一知识只有一处权威定义；其他地方只放指针或标注来源的摘要。

- 违反：两个文档各自定义 `e.payments`，改一处漏一处。
- 校验点：L4 跨文档 id 冲突检测；`imports` 而非复制。

## H11 HTML 中不得直接改语义

浏览器端只能产生**批注**与**补丁请求**；改元素/关系必须回到 CLI/服务，经校验与批准。

- 违反：没有校验器的写入产生非法文档。
- 校验点：viewer 的写接口只有 annotations；schema 拒绝其他 op。

## H12 审计不可删改

`.audit/` 记录一旦写入不得编辑；只能追加。

- 违反：无法回答"谁批准了这个破坏性变更"。
- 校验点：审计文件只追加；写入前先写 intent（write-ahead）。

---

## 违反后果分级

| 级别 | 情形 | 处理 |
|------|------|------|
| **P0 阻断** | 违反 H1/H3/H4/H6/H12 | 拒绝提交；已合并的需回滚并写事故记录 |
| **P1 严重** | 违反 H2/H5/H7/H8/H11 | 拒绝发布，修复后方可继续 |
| **P2 一般** | 违反 H9/H10 | 记录技术债，下个迭代内修 |

> 判定口径：**"是否让事实源失真或让审计失效"** —— 是则 P0/P1，否则 P2。
