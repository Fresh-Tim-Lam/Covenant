## `paradigm-spec-v2.md` 结构（已成稿）

> 实际采用 11 节 + 5 个附录。核心设计：**每条规则都有判定方式（CI / Review / Self），无法判定的句子不进规范。**

1. 适用范围与前提（含"不应使用"的判据）
2. 目录契约（一级目录 / 根白名单 / 临时区 / 模块语料 / D1–D6）
3. 索引契约（FRAS 五字段 / 更新触发 / 新鲜度 / 读写隔离 / I1–I4）
4. **图示契约**（最小图集 / 必填字段 / L0–L6 / finding 可执行 / ai_hint 六条句式规则 / 图码互链 / G1–G8）
5. 补丁与批准（base_rev + intent / 三类 diff / 批准矩阵 / write-ahead 审计 / P1–P4）
6. 最小角色（只到"谁对哪份契约负责"，不做组织设计）
7. 新项目 0→1（8 步，半日到 1 天，含验收标准）
8. 度量（6 项指标与目标）
9. 自检清单（仓库级 + 变更级）
10. 存量项目迁移（三阶段，禁止一次性大改）
11. 规范自身的可执行性（1 天可落地；规则必须有判定方式；变更走 ADR）
- 附录 A–E：目录 README / FRAS / 图示骨架 / 批注 / ADR

## 写作纪律

1. 宣言里不写操作步骤；规范里不写动机。
2. 每条规则必须**可判定**（能写成检查项），否则不写进规范（可留在宣言）。
3. 所有图先用 Mermaid 占位，并在图下标注"将在 M2 后被 `.cvn` 生成图替换"。
4. 不复制 Covenant 的专有细节（如具体剖面名），用"参考实现"链接代替。
