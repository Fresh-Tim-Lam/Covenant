# docs 管理规范

> **用途**：定义 `docs/` 的子目录职责、文档书写格式与索引维护规则，保证文档**唯一落位、不双源漂移**。
> **目标读者**：人 + AI Agent（新增/移动/删除文档前必读）。
> **状态**：生效中（核验于 2026-11-03）。
> **关联**：[README.md](README.md)、[directory-organization.md](directory-organization.md)。

## 1. 子目录职责

| 目录 | 职责（类型） | 内容示例 |
|------|------------|---------|
| `research/` | 外部调研与对标 | 市面项目、标准、论文笔记 |
| `design/` | 设计提案、格式规范、架构决策 | 格式、引擎、剖面、门禁、自举 |
| `conventions/` | 契约性规范（人机都遵守） | 本目录 |
| `reference/` | 参考说明（是什么/为什么） | 术语表、硬约束 |
| `guides/` | 操作指引 how-to | M1 后补 |
| `prompts/` | 可复制的范式与提示词模板 | 宣言、规范 |
| `sessions/` | 历史对话/交接记录 | — |
| `example/` | 示例与测试语料 | 暂由仓库根 `examples/` 承担 |
| `tmp/` | 少量诊断记录 | — |

**`docs/` 根只允许**：`README.md`（总索引）+ `to-dolist.md`（活跃待办）。其余文档按上表唯一落位。

## 2. 命名

- 一律 **kebab-case 英文语义**：`format-spec-v0.md`、`gate-spec-v0.md`。
- 中文文件名先转英文语义，再 kebab-case。
- 版本化文档用 `-v0` / `-v2` 后缀；**不要把日期塞进文件名**（除调研快照等时间敏感物，如 `landscape-2026-11.md`）。

## 3. 头部三要素（每份文档前 1–3 行必须有）

```markdown
> **用途**：<独立可读的一句话；禁止"详见 xxx">
> **目标读者**：<谁>
> **状态**：<生效中｜草案｜已废弃>（核验于 YYYY-MM-DD）
> **关联**：[...](...)
```

违反三要素视为未完成，不得被正式引用。

## 4. 单一事实源 + 防双源漂移

- 同一知识只维护**一份权威文档**；
- 需要摘要时，在摘要处标注「摘要同步自 X，冲突以 X 为准」；
- 内容变更必须同步摘要；**禁止两份平级描述**。

## 5. 索引维护（强制）

新增 / 移动 / 删除文档后，**创建者必须**：

1. 同步父目录 `README.md` 索引；
2. 若是新目录，登记到本文件 §1 与 `docs/README.md` 子目录表。

**索引里不写"共 N 篇"这类硬计数**——计数必然过期；用清单或"见下"代替。

## 6. 文档状态标注

| 状态 | 含义 |
|------|------|
| 生效中 | 现行规则，必须遵守 |
| 草案 | 可引用但可能变更，引用时标注 |
| 已废弃 | 仅保留历史，不得再依据 |

## 7. 自检

- [ ] 文档在正确子目录，文件名 kebab-case
- [ ] 头部三要素齐全
- [ ] 父目录 README 已登记
- [ ] 无与权威源平级的重复内容
