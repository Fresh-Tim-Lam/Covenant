# 规范元规则（meta-rules）

> **用途**：规定"如何制定与修改规范"本身——防止规范腐烂、漂移、只写不执行。
> **目标读者**：人 + AI Agent（修改任何规范前必读）。
> **状态**：生效中（核验于 2026-11-03）。
> **关联**：[README.md](README.md)、[../prompts/paradigm-spec-v2.md](../prompts/paradigm-spec-v2.md) §11。

## 1. 结论即落盘（1 轮内）

任何讨论产生明确结论（采纳 / 拒绝 / 暂缓）后，**必须在 1 次对话轮内**更新到对应规范文档。

Agent 每次响应前先读最新规范；规范变更后输出 `[上下文已同步] 规则 xxx 已更新`。

## 2. 结论必有状态标记

议题最终状态必须显式标记：

- `✅ 采纳`
- `❌ 不采纳`
- `⏳ 暂缓`（必须注明阻塞项）

**未标记 = 未关闭**，进入下一轮继续讨论。

## 3. 规则必须绑定场景

每条规则必须关联具体场景，标题或说明带 `[场景名]` 前缀；纯抽象规则不写入规范（留在宣言或设计文档）。

## 4. 只写可判定的规则

**无法判定（CI / Review / Self）的句子不进规范。** 规范里只有能检查的规则；理念与价值判断放 `docs/prompts/paradigm-declaration-v2.md`。

> 这条是防止"规范看起来很专业但没人执行"的第一道闸。

## 5. 不为不存在的东西立规矩

规范的触发条件是**产物已存在或即将存在**。例：没有源码就不写版本规范；没有日志就不写日志规范。

## 6. 违规后果分级

| 级别 | 情形 | 处理 |
|:----:|------|------|
| 轻度 | 1 轮内未同步更新 | 暂停当前讨论，先补更新 |
| 重度 | 跨会话未更新 | 结论视为未生效，需重新确认 |
| 严重 | 规范与实现长期不一致 | 写 ADR 说明，二选一：改规范或改实现 |

## 7. 单一事实源纪律

版本号、格式字段、规则编号、决策编号等"多处需要一致"的信息**只放一处权威源**，其余只放指针。

已知权威源：

| 信息 | 权威源 |
|------|--------|
| 格式字段 | `docs/design/format-spec-v0.md` + `schema/kernel.schema.json` |
| 剖面词表/规则类型 | `docs/design/profiles-catalog-v0.md` |
| 决策 D1–D4 / Q5–Q10 | `docs/design/open-questions.md` |
| 范式决策 P1–P6 | `docs/prompts/README.md` |
| 任务 | `docs/to-dolist.md` |

## 8. 改规范的联动要求

改规范时，同一次提交内必须检查：

1. 是否影响 `schema/`（字段/枚举）→ 同改；
2. 是否影响 `examples/`（示例是否仍合法）→ 同改；
3. 是否影响 `AGENT.md` 的 Conventions 表 → 同改；
4. 是否影响索引 → 同改。

## 9. 协作问答规则

- 存疑即停，先问后做；
- 反问必须**带选项并给出推荐**；
- 先用尽自解手段再问；
- 对齐后按结果执行；低风险事务不阻塞等待。
