## 风险 / 待补（2026-11-03 由 lead 实测暴露）

- **R-01 编辑通道与 patch-check 仍是两套校验**：`edit` 仅有 `checkDocument`（0 error 才写）+ human-only actor 门禁（`packages/cli/src/index.ts:686-692`）+ 备份 + 审计；**未复用** `patch-check` 的越权 / author 一致性 / 状态流转等规则 → T6 补齐前，`apply` 仍是唯一"全规则"合规写回通道；AI 不得用 `edit` 改语义（已由 human-only 拦截）。
- **R-02 `pnpm edit` 不可用**（见 D-011）：文档、示例、提示语统一写 `pnpm covenant edit`。
- **R-03 preview 产物落在源目录**（静态推断，**未实测**）：默认输出 `<doc>.edited.cvn.yaml` 与源文档同目录，会被 `covenant check <目录>` 当作文档扫描（`packages/cli/src/index.ts:61-65`）→ 建议 `--out` 到临时目录或加入忽略清单。
- **R-04 修订号语义**：accept 时 `meta.rev+1`（实测 1→2，`cmdEdit` L693），与 `apply` 的 rev+1 同义；preview 不 bump（正确），但 `--out` 若与源同目录，注意别把 edited 文件误当事实源（D-002）。
- **R-05 坐标编辑是 layout 坐标、非拖拽**（**由 lead 实测**）：表单 X/Y 来自构建期 `doc.positions[id]`（`html.ts:346-347`），写入 `layout.pins`（`html.ts:611`）；**不是**鼠标拖拽改坐标，拖拽编辑未实现。多视图时写入 `doc.viewId || doc.defaultViewId`（`html.ts:608-609`），归属需实测确认。
- **R-06 `edit --accept` 丢注释**（**由 lead 实测**）：`serializeDoc`（`packages/editor/src/index.ts:164`）重新生成 YAML，注释不保留（`.audit/*.bak` 可回滚）；与 `apply` 的"文本块插入、保留注释"不同 → 影响 git diff 可读性，需 Q1/Q3 决定写回路径。
- **R-07 导出的 edits.json 需人工转移**（**由 lead 实测/提示**）：下载到浏览器默认下载目录，需人工移到项目内或把路径传给 `covenant edit`；无自动交付步骤。
- **R-08 本地编辑服务的安全面**（静态核对）：`serve --edit` 仅 loopback + 启动时随机 token 注入页面（`__CVN_EDIT__`）+ human-only + 写前 `checkDocument`（`serve.ts` L5-7、L119-121）；但**带 token 的页面/URL 不可分享**，端口转发/共享会放大风险；`docs/guides/agent-team-edit-deployment.md` 要求只在本机使用。
